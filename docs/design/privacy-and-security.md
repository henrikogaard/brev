# Privacy & Security

> Consolidates former ADRs `0006`, `0021`, `0036`, `0055`, `0082`, and `0088`.
> User-facing counterpart: [PRIVACY.md](../../PRIVACY.md).

## Hard Invariants

1. **Zero telemetry, mechanically enforced.** Brev contains no analytics SDK, no crash reporter, no usage beacons, and no opt-in telemetry. Imports of `Matomo`, `Sentry`, `FirebaseAnalytics`, `Mixpanel`, and `Amplitude` are banned by SwiftLint and verified against built artifacts by `scripts/test-telemetry-artifacts.sh` and `scripts/privacy-audit.sh`.
2. **No Brev-operated mail proxy or cloud server.** Brev connects directly from the user's device to the user's chosen mail, DAV, or AI endpoints. Ogard Labs (`privacy@brevmail.eu`) stores no user mailbox data, credentials, or analytics.
3. **Keychain-only secrets.** IMAP/SMTP passwords, app passwords, OAuth tokens, and BYOK AI API keys live exclusively in the macOS or iOS Keychain—never in `UserDefaults`, logs, crash reports, or portable backups.
4. **No silent third-party leaks.** Tracking pixels are stripped before rendering, the sandboxed `WKWebView` reader disables JavaScript, and every new external network call must be documented both in the ledger below and in [PRIVACY.md](../../PRIVACY.md).
5. **Demo mode isolation.** Demo/mock sessions (`BREV_USE_MOCK=1`) never access system Contacts, system Calendar, or real Keychain/DAV credentials.

## Balanced Privacy Posture (Updated from Legacy ADRs)

Zero telemetry and zero Brev-operated proxy servers remain non-negotiable. However, rather than burying every benign convenience behind eight disconnected Settings toggles:

- **Onboarding choices:** First-run setup presents an optional, plain-language **Privacy & Convenience Choices** walkthrough (`PrivacyOnboardingSheet`) after a brand-new user finishes adding their first real account (suppressed during demo/mock mode, automated tests, snapshot runs, and for existing users with restored accounts or already-customized settings). Every opt-in convenience remains strictly `false` by default (sender domain/Gravatar avatars, trusted-sender remote images, iCloud preference sync, macOS background mail checks, background recent-mail & attachment indexing, and zero-network on-device Apple Intelligence + optional proactive on-device triage; cloud/BYOK AI providers are never configured in onboarding). Choosing **Keep defaults (all off)** or dismissing leaves every opt-in off, records only a device-local completion flag (`onboarding.privacyChoices.completed`, excluded from `PreferenceSyncAllowlist` and `.brevbackup`), and never nags again. Users can reopen the walkthrough anytime from **Settings → Privacy & Security → Privacy → Review Privacy & Convenience Choices…**, pre-populated with current settings and applying only explicit edits on Save.
- **Trusted-sender remote images:** Remote HTML assets remain blocked by default for unknown senders (with tracking pixels stripped), while supporting explicit per-sender/per-domain allowlists and an opt-in **Load remote images for trusted senders** tier (`body.allowRemoteContentForTrustedSenders`, default `false`, excluded from iCloud preference sync) that matches exact normalized sender addresses locally against already-authorized Contacts / cached PIM contacts and locally recorded outgoing/replied-to recipients (never prompting for Contacts permission, never domain-only matching, and continuing to strip tracking pixels whenever `stripTrackingPixels` is enabled).
- **Sign-in code trust on generic IMAP:** See Sign-In Code Detection below—generic IMAP accounts are no longer permanently disqualified when standard authentication headers or explicit user opt-in are used.

## Local Store Encryption at Rest

- **Layer A (OS file protection — shipped):** `SQLiteSyncStore`, `SQLiteGmailAccountStore`, header/body/source caches, local mail folders, and staging files open standard SQLite/file stores under `~/Library/Application Support/Brev`. On iOS, `BrevStoreProtection` applies `FileProtectionType.completeUntilFirstUserAuthentication` to the store root and its contents; on macOS, `BrevStoreProtection` is a no-op and at-rest confidentiality relies on FileVault and the user's sandboxed home container (explicit `0600`/`0700` POSIX modes are strictly enforced on the local MCP Unix socket and its parent directory).
- **Layer B (application-level encryption — planned):** Application-level encryption of local SQLite databases and cached payloads using device-scoped Keychain keys (`eu.brevmail.brev` / `eu.brevmail.brev.ios`, never shared across platforms or exported in backups) is planned future work and is not yet implemented in `SQLiteSyncStore` or `SQLiteGmailAccountStore`.
- **Logs:** Local errors write to `~/Library/Logs/Brev/brev.log` (macOS) or the app container (iOS) with secrets, tokens, message bodies, and sign-in codes strictly redacted; logs are never transmitted automatically.

## S/MIME Security

- `BrevCrypto` encapsulates all cryptographic operations so views and mail adapters never see low-level CMS/Security types.
- **Inbound verification & decryption:** Supported on both macOS and iOS with clear signature/encryption badges in the reader.
- **Outbound signing & encryption:** Supported on both macOS and iOS using local Keychain certificates and identities only (zero network or directory lookups). macOS uses Apple's `CMSEncoder` and iOS uses `BrevCrypto`'s pure-Swift RFC 8551 / RFC 5652 CMS DER encoder (`PureSwiftCMSEncoder`, built solely on `Security`, `CryptoKit`, and `CommonCrypto` with SHA-256 detached `SignedData` for RSA/ECDSA keys and AES-256-CBC + RSA PKCS#1 `EnvelopedData`). Both platforms fail closed via `OutboundMessageSecurityPolicy` rather than silently downgrading to plaintext when requested security cannot be satisfied.
- OpenPGP is retired (`scripts/test-openpgp-retired.sh`).

## Sign-In Code & Link Detection

- Device-local, per-account opt-in (`SignInCodeSettings`, off by default, excluded from backups and iCloud sync).
- Extracted one-time codes and HTTPS sign-in links stay **memory-only** (never logged or persisted), copy to clipboard as concealed/expiring entries (`org.nspasteboard.ConcealedType` on macOS; `.localOnly` with 60-second expiry on iOS), and post **lock-screen-safe** generic local notifications on iOS (zero raw codes or links in `UNNotificationContent`, biometric-gated Copy action, foreground host-confirming Open Link action).
- **Generic IMAP support (shipped, #5):** Public-hostname generic IMAP/SMTP accounts (such as Fastmail, iCloud IMAP, Gmail IMAP, Outlook/Exchange IMAP, Migadu, Mailbox.org, and custom domains) with established non-local receiving-server provenance and header-only `BODY.PEEK[HEADER]` support advertise `.trustedSignInAssessment`, while remaining **off by default** per account. Loopback and IP-literal IMAP hosts (such as default Proton Bridge on `127.0.0.1`) fail closed and do not advertise `.trustedSignInAssessment` because receiving-server provenance cannot be verified from a loopback host. Before reading a message body, Brev checks live Inbox fresh-delivery provenance, enforces the 10-minute freshness window against IMAP server `INTERNALDATE`, fetches only raw RFC 5322 headers (`BODY.PEEK[HEADER]` when not already cached; never falls back to full `BODY.PEEK[]`), and verifies the top-most receiving-server `Authentication-Results` header (RFC 8601) at the top receiving boundary (only trusted delivery hops above it, `authserv-id` matching the account's trusted receiver boundary): requiring `dmarc=pass` with `header.from` matching a single RFC 5322 `From` mailbox domain plus at least one aligned `dkim=pass` (`header.d`/`header.i`) or `spf=pass` (`smtp.mailfrom`/`smtp.helo`). Messages that fail, lack authentication headers, come from an untrusted `authserv-id`, or fail header fetch are dropped closed without reading the body.

## Local MCP Agent Access Security

- Transport is strictly a user-private `0600` `AF_UNIX` socket scoped per app bundle identity (Stable, Nightly, Test) with `getpeereid` same-UID verification on **both** the server and the bundled `brev-mcp` stdio helper. Zero TCP or UDP ports.
- Master switch and per-account grants default to off, stay device-local, and are excluded from backups and iCloud sync.
- Read tools are cache-only, exclude Trash/Spam, and redact sign-in codes/links; write tools require per-call in-app approval with a 60-second fail-closed timeout; `send_message`, `delete_message`, and settings/credential mutations are permanently excluded.
- Bounded 1,000-entry backup-excluded local audit log (`agent-access-audit.json`) never records bodies, snippets, credentials, or unresolved caller-supplied IDs.

## GDPR & Crash Reporting

- **Controller:** Ogard Labs (`privacy@brevmail.eu`). Right to erasure is uninstalling the app; mail stays on the user's provider.
- **Crash logs:** No third-party crash SDK. Diagnostics come only from Apple's opt-in App Store Connect crash aggregation or logs a user deliberately attaches to a GitHub issue.
